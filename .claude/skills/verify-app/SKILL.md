# verify-app · ตรวจแอปก่อนบอกว่าเสร็จ

ทำทุกขั้นตามลำดับ ห้ามข้าม ห้ามสรุปว่าผ่านจากความจำหรือจากการอ่านโค้ด ต้องมาจากผลที่รันในรอบนี้เท่านั้น

## 1. เปิด dev server
- รันแบบเบื้องหลัง (Bash `run_in_background: true`) จากรากของ repo:
  `python3 -m http.server 8000`
- รอจนพร้อม: `until curl -sf http://localhost:8000/ >/dev/null; do sleep 0.5; done` (ใส่ timeout 30 วินาที)
- ถ้าพอร์ต 8000 ถูกใช้อยู่ ให้ใช้พอร์ตอื่น แล้วเปลี่ยน `BASE_URL` ในขั้นถัดไปให้ตรงกัน

## 2. รัน test ที่เกี่ยวข้อง
1. ดูว่าแก้อะไรไป: `git diff --name-only origin/main` และ `git status -s`
2. เทียบไฟล์ที่แก้กับ "ไฟล์หลัก" ของแต่ละฟีเจอร์ใน `FEATURE_MAP.md` แล้วจดว่าฟีเจอร์ไหนเกี่ยวข้อง
3. รัน flow หลักผ่าน dev server ทุกครั้ง (ใช้เวลาราว 20 วินาที):
   `BASE_URL=http://localhost:8000/ node tests/flows.js`
4. รันข้อ e2e ของฟีเจอร์ที่เกี่ยวข้อง โดยใช้คำในชื่อข้อตามบรรทัด **test** ของ FEATURE_MAP เช่น
   `node tests/e2e.js "ไวยากรณ์"` (ชุดนี้เปิด server ของตัวเอง)
5. ก่อนบอกว่าเสร็จ รันทั้งชุด: `npm run check` (type → lint → unit → hooks → e2e → flows ราว 3–4 นาที) และ `node tests/check-version.js origin/main`
6. ถ้าแก้แมวพิกเซลหรือฉาก ให้รัน `node tests/pet-grid.js test-results/pet-grid` เพิ่มด้วย

## 3. เปิดดูภาพหน้าจอ
- หลักฐานอยู่ใน `test-results/flows/` และ `test-results/e2e/` (ดูรายชื่อภาพของแต่ละข้อได้ใน `summary.md`)
- ใช้ Read เปิดภาพจริงอย่างน้อย 1 ภาพต่อ flow ที่เกี่ยวข้อง และทุกภาพของข้อที่ไม่ผ่าน (`<ข้อ>-end-p1.png` คือหน้าจอตอนจบข้อ)
- ดูว่าภาพตรงกับที่ flow ควรเป็น: ข้อความไทยไม่ล้น ไม่มีหน้าว่าง ไม่มีส่วนที่ซ้อนทับกัน และปุ่มอยู่ในจอ
- ถ้าภาพผิดแต่ test ผ่าน ให้ถือว่าไม่ผ่าน และบอกว่า test ยังจับจุดนั้นไม่ได้

## 4. อ่าน console error
- `grep -n "\[p[0-9]* \(error\|pageerror\)\]" test-results/*/*.console.log`
- ข้อที่ไม่ผ่าน: อ่าน `test-results/<ชุด>/<ข้อ>.console.log` ทั้งไฟล์ (บรรทัดบนสุดคือข้อผิดพลาดของ test)
- `warning` ที่เป็น "Service Worker registration blocked by Playwright" เกิดจากการตั้งค่าของ test เอง ไม่ใช่ปัญหาของแอป

## 5. สรุป
ตอบเจ้าของด้วยตารางนี้ หนึ่งแถวต่อ flow ที่รัน:

| flow | ผ่าน/ไม่ผ่าน | หลักฐาน |
|---|---|---|
| ชื่อ flow ตาม FEATURE_MAP | ✅ ผ่าน / ❌ ไม่ผ่าน (สาเหตุสั้นๆ) | ชื่อไฟล์ภาพ · จำนวน console error · บรรทัดผล test |

แล้วตามด้วย:
- บรรทัดสรุปผลจริงของแต่ละชุด เช่น `ผ่านทั้งหมด 58 ข้อ` หรือ `ไม่ผ่าน 1/7`
- อะไรที่ยังไม่ได้ตรวจ (เช่น iPad Safari จริง, Apple Pencil จริง)
- ข้อที่ไม่ผ่าน: บอกตรงๆ ว่าไม่ผ่าน ห้ามบอกว่าเสร็จ ห้ามแก้ test ให้ผ่านโดยไม่แก้ต้นเหตุ

## 6. ปิด dev server
หยุด process ที่เปิดในขั้นที่ 1 (KillShell / `kill <pid>`)
