### ง · `catch` ที่กลืน error เงียบ (91 = no-empty 38 + catch ไม่ใช้ตัวแปร 53 · ใหญ่สุด · ทำหลัง จ) ✅ v159 · เหลือ 0
ทำแล้ว (เหลือ 74 หลังกลุ่ม ข–จ · เจ้าของอนุมัติรหัส ง0–ง7): ฟังก์ชันอ่าน/เขียนย้ายไป `js/level.js` (โหลดก่อน `core.js`) รองรับ sessionStorage · อ่าน/ลบผ่านฟังก์ชันนี้ · **เขียนไม่ได้ (พื้นที่เต็ม/โหมดส่วนตัว) แจ้งผู้ใช้ครั้งเดียวต่อการเปิดแอป** · เข้าสู่ระบบด้วย Google เก็บ code_verifier ไม่ได้ → ไม่ไปหน้า Google และบอกให้ใช้อีเมล · ปุ่มฟังเสียงเล่นไม่ได้ → แจ้งผู้ใช้ · งานเน็ตที่ไม่จำเป็นต้องสำเร็จและ API ของเบราว์เซอร์ที่ไม่มีค่าทดแทน → `console.warn` พร้อมบริบท · มีค่าทดแทนอยู่แล้ว → `catch {` · e2e ใหม่ "ที่เก็บข้อมูลในเครื่องเขียนไม่ได้"
ส่วนใหญ่เป็น `JSON.parse(localStorage…)` และ `localStorage.setItem` ที่ล้มได้ในโหมดส่วนตัวหรือพื้นที่เต็ม
- หลังทำกลุ่ม จ แล้ว จุดอ่าน/เขียน localStorage จะไปรวมอยู่ใน `readJSON`/`writeJSON` ทำให้เหลือ `catch` ไม่กี่ที่
- ที่เหลือแยกเป็น 2 แบบ: ล้มแล้วไม่เป็นไรจริงๆ → `catch {` (ไม่ประกาศตัวแปร) และเพิ่ม test ที่ยืนยันว่าแอปยังทำงานเมื่อที่เก็บข้อมูลล้ม · ล้มแล้วผู้ใช้เสียข้อมูล → แสดงข้อความให้ผู้ใช้เห็น (เช่นบันทึกไม่ได้เพราะพื้นที่เต็ม)
- ห้ามแก้ด้วยการใส่ comment ใน `catch` ว่างเพื่อให้กฎผ่าน (ขัดกับกฎ comment ใน CLAUDE.md)
