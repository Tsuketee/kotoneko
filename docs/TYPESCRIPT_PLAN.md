## วิธีที่เสนอ: JSDoc + `// @ts-check` ก่อน (ไม่มีขั้นตอน build)
เบราว์เซอร์รันไฟล์ `.ts` ไม่ได้ ถ้าย้ายเป็น `.ts` จริงต้องเพิ่มขั้นตอน build ทำให้ deploy บน GitHub Pages และการแคชของ `sw.js` เปลี่ยนไปทั้งหมด จึงเสนอให้ทำ 2 ระยะ:
1. **ระยะ 1 (เสนอให้ทำ)**: ยังเป็น `.js` เหมือนเดิม แต่ใส่ type ด้วย JSDoc แล้วให้ `tsc --checkJs` ตรวจ ทีละไฟล์ ได้ประโยชน์ของ type check เกือบทั้งหมดโดยไม่ต้อง build
2. **ระยะ 2 (ตัดสินใจทีหลัง)**: เปลี่ยนเป็น `.ts` จริงพร้อม build (เช่น esbuild ออกเป็น `js/`) เมื่อทุกไฟล์ผ่านระยะ 1 แล้ว

TypeScript มองไฟล์ที่ไม่มี import/export เป็น script ที่ใช้ global ร่วมกันอยู่แล้ว จึงเข้ากับโครงสร้างตอนนี้ได้โดยไม่ต้องแก้ลำดับ `<script>`

## ขั้นตอนต่อหนึ่งไฟล์
1. เพิ่มไฟล์นั้นใน `include` ของ `tsconfig.json` (ตั้ง `allowJs: true`, `checkJs: true`)
2. ใส่ JSDoc ให้ข้อมูลและฟังก์ชันที่ไฟล์นั้นประกาศ (`/** @typedef */`, `/** @param */`)
3. แก้จน `npm run typecheck` เป็น 0 แล้ว `npm run check` ผ่าน · ไฟล์ที่เข้าแล้วห้ามถอยออก (CI ตรวจ)
4. หนึ่ง PR ต่อหนึ่งกลุ่มด้านล่าง

ก่อนเริ่มไฟล์แรก ต้องมี `types/globals.d.ts` ประกาศ `window.PixelCat`, `window.TownMap` และรูปร่างข้อมูลหลัก (คันจิ คำ บทสนทนา ไวยากรณ์ สถานะ SRS `{b, w, d}` และ `M` ใน `kn_meta`) เพราะ error "หาชื่อไม่เจอ" ทั้ง 17 จุดมาจากสองชื่อนี้
