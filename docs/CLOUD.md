# ตั้งค่าบัญชีผู้ใช้และซิงก์คลาวด์ (Supabase)

แอปใช้ Supabase แพ็กเกจฟรี เก็บความคืบหน้าบนคลาวด์ เข้าสู่ระบบด้วย **รหัสตัวเลขทางอีเมล** (ไม่มีรหัสผ่าน)
ถ้ายังไม่ตั้งค่า (`js/data/cloud-config.js` ว่าง) แอปจะซ่อนส่วนบัญชีทั้งหมด และทำงานในเครื่องอย่างเดียวเหมือนเดิม

## ขั้นตอน (ทำครั้งเดียว ประมาณ 10 นาที)

1. **สร้างโปรเจกต์** ที่ https://supabase.com → New project (เลือก Region ใกล้ไทย เช่น Singapore) ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้
2. **สร้างตารางและฟังก์ชัน** (รวมฟังก์ชัน `delete_my_account` ที่ใช้กับปุ่ม "ลบบัญชี" ในแอป ถ้าเคยรันไฟล์นี้ไปแล้วก่อนมีฟังก์ชันนี้ ให้รันใหม่อีกครั้ง รันซ้ำได้ปลอดภัย): เมนู SQL Editor → New query → วางเนื้อหาทั้งไฟล์ `supabase/schema.sql` → Run
3. **ตั้ง Custom SMTP ก่อน แล้วค่อยแก้แม่แบบอีเมล** (ข้อนี้ข้ามไม่ได้)
   Supabase ไม่ให้แก้แม่แบบอีเมลถ้ายังไม่ตั้ง SMTP และอีเมลเริ่มต้นมีแต่ลิงก์ ไม่มีรหัสตัวเลข ซึ่งแอปบน iPad ใช้ไม่ได้ เพราะแอปที่เพิ่มลงหน้าจอโฮมแยกที่เก็บข้อมูลจาก Safari ลิงก์จะไปเปิดใน Safari แทน
   1. สมัครผู้ให้บริการส่งอีเมล เช่น **Brevo** (ฟรี 300 ฉบับต่อวัน ยืนยันอีเมลผู้ส่งตัวเดียวก็ใช้ได้ ไม่ต้องมีโดเมน) แล้วเพิ่มผู้ส่งที่ Settings → Senders, Domains & Dedicated IPs → Senders และยืนยันด้วยรหัสที่ส่งไปทางอีเมล
   2. Brevo: Settings → SMTP & API → แท็บ SMTP → **Generate a new SMTP key** (เห็นครั้งเดียว)
   3. Supabase: Authentication → Emails → **SMTP Settings** → เปิด Custom SMTP แล้วกรอก
      - Sender email: อีเมลที่ยืนยันกับ Brevo แล้ว · Sender name: `Kotoneko`
      - Host `smtp-relay.brevo.com` · Port `587`
      - Username: ค่า **Login** จากหน้า SMTP ของ Brevo (ไม่ใช่ชื่อบัญชี) · Password: SMTP key
   4. แท็บ **Templates** แก้ทั้ง **Confirm sign up** และ **Magic link or OTP** (โหมด Source) ให้มี `{{ .Token }}`
      ```html
      <h2>รหัสเข้าสู่ระบบ Kotoneko</h2>
      <p>กรอกรหัสนี้ในแอป:</p>
      <p style="font-size:28px;letter-spacing:6px"><b>{{ .Token }}</b></p>
      <p>ถ้าคุณไม่ได้ขอรหัสนี้ ไม่ต้องทำอะไรค่ะ</p>
      ```
   > ⚠️ SMTP key เป็นความลับ กรอกในหน้า Supabase เท่านั้น ห้ามวางในแชท โค้ด หรือ commit ถ้าเผลอเปิดเผย ให้ลบคีย์นั้นใน Brevo แล้วสร้างใหม่ทันที
   > อีเมลที่ส่งจาก Gmail อาจเข้าสแปม ก่อนเปิดขายจริงควรใช้โดเมนของตัวเอง
4. **คัดลอกคีย์:** เมนู Project Settings → API (หรือ Data API / API Keys)
   - Project URL เช่น `https://abcdefgh.supabase.co`
   - คีย์ **anon / publishable** (ห้ามใช้ `service_role` / secret เด็ดขาด)
5. **ใส่ในแอป:** แก้ `js/data/cloud-config.js`
   ```js
   const CLOUD = { url: 'https://abcdefgh.supabase.co', key: 'คีย์ anon' };
   ```
   แล้วเพิ่มเลข `VERSION` ใน `sw.js` → commit → push เข้า `main`

## แก้ปัญหา
- **อีเมลมีแต่ลิงก์ ไม่มีรหัส:** ยังไม่ได้ตั้ง SMTP หรือยังไม่ได้แก้แม่แบบตามข้อ 3
- **ช่อง Host ขึ้นแดง:** ใส่ชื่อบัญชีแทนที่อยู่เซิร์ฟเวอร์ Host ต้องเป็น `smtp-relay.brevo.com`
- **อีเมลไม่มา:** ดูกล่องสแปม แล้วเช็กที่ Brevo → Transactional → Logs ถ้าไม่มีรายการ แปลว่าค่า SMTP ใน Supabase ผิด (มักเป็น Username หรือ Password)
- **หน้าพรีวิวแม่แบบว่าง:** เป็นปกติของหน้านั้น ดูผลจากอีเมลจริง

## ก่อนเปิดขายจริง
- ใช้โดเมนของตัวเองเป็นผู้ส่ง (ยืนยันโดเมนกับ Brevo หรือเปลี่ยนไปใช้ Resend, Amazon SES) เพื่อไม่ให้อีเมลรหัสเข้าสแปม
- โปรเจกต์ฟรีจะถูกพักถ้าไม่มีการใช้งาน 7 วัน (ข้อมูลไม่หาย กดเปิดใหม่ได้) ถ้ามีผู้ใช้จ่ายเงินแล้วควรอัปเกรดเป็นแพ็กเกจ Pro
- อัปเดตนโยบายความเป็นส่วนตัว: เก็บอีเมลและความคืบหน้าการเรียนไว้ที่ Supabase (ข้อในเฟส 4)

## ทำงานอย่างไร
- ผู้ใช้ 1 คน = 1 แถวในตาราง `progress` เก็บทุก key ความคืบหน้า (`ka1` `kn5` `kw1` `kv1` `kg1` `kn_meta`) เป็นก้อนเดียว
- ซิงก์ครบตอนเปิดแอป กลับเข้าแอป ต่อเน็ตได้อีกครั้ง และกด "ซิงก์ตอนนี้" · ส่งขึ้นอย่างเดียวทุก 2 นาทีระหว่างเรียนและตอนสลับออกจากแอป
- ส่งขึ้นแบบมีเงื่อนไขด้วยเลข `rev` ถ้าเครื่องอื่นส่งขึ้นไปก่อนจะไม่เขียนทับกันเงียบๆ
- ถ้าทั้งเครื่องนี้และคลาวด์มีของใหม่ทั้งคู่ แอปจะถามให้เลือกฝั่งที่จะเก็บ
- สถานะการเข้าสู่ระบบเก็บใน `localStorage` key `kn_cloud` (ไม่ถูกส่งออก/ซิงก์)
- เครื่องใหม่: ตอนตั้งค่าครั้งแรกกด "มีบัญชีอยู่แล้ว? เข้าสู่ระบบ" เพื่อดึงข้อมูลเดิมมาได้เลย

## เนื้อหาเสียเงิน (N4 …)
เนื้อหาเสียเงินไม่อยู่ใน repo นี้ (public) ต้นฉบับอยู่ใน repo private `kotoneko-content` และส่งให้ผู้มีสิทธิ์ผ่าน Supabase
- ตาราง `entitlements` (ใครปลดล็อกระดับไหน) · `content_packs` (แพ็กเนื้อหาแต่ละระดับ) · `admins` (ผู้ดูแลที่อัปโหลดแพ็กได้) อยู่ใน `supabase/schema.sql`
- RLS: อ่านแพ็กได้เฉพาะผู้มีสิทธิ์ระดับนั้นหรือผู้ดูแล · เขียนแพ็กได้เฉพาะผู้ดูแล · แอปเพิ่มสิทธิ์ให้ตัวเองไม่ได้ (เพิ่มจาก SQL Editor หรือ webhook ชำระเงินฝั่งเซิร์ฟเวอร์เท่านั้น)
- การซื้อด้วย Stripe (เพิ่มสิทธิ์อัตโนมัติผ่าน Edge Function) ดูวิธีตั้งค่าใน `docs/PAYMENT.md`
- แอปดาวน์โหลดแพ็กครั้งแรกที่กดเปลี่ยนเป็นระดับนั้น เก็บใน `localStorage` ใช้ออฟไลน์ได้ ตรวจเวอร์ชันใหม่ทุกครั้งที่เปิดแอป · ออกจากระบบ ลบบัญชี หรือถูกถอนสิทธิ์ จะลบแพ็กออกจากเครื่องและกลับไป N5

### ตั้งค่าครั้งแรก (SQL Editor)
1. รัน `supabase/schema.sql` ใหม่ทั้งไฟล์ (รันซ้ำได้)
2. ตั้งตัวเองเป็นผู้ดูแล: `insert into public.admins (user_id) select id from auth.users where email = 'อีเมลของคุณ' on conflict do nothing;`
3. ให้สิทธิ์ทดสอบ: `insert into public.entitlements (user_id, level, source) select id, 'n4', 'manual' from auth.users where email = 'อีเมล' on conflict do nothing;`
   ถอนสิทธิ์: `delete from public.entitlements where level = 'n4' and user_id = (select id from auth.users where email = 'อีเมล');`

### อัปโหลด / อัปเดตแพ็ก
1. ใน repo เนื้อหา: รันตัวตรวจทุกตัวให้ผ่าน แล้ว `python3 -I tools/build_pack.py n4` ได้ไฟล์ `packs/n4.json`
2. ในแอป (เข้าสู่ระบบด้วยบัญชีผู้ดูแล): สถิติ → บัญชีและซิงก์ → ส่วน "ผู้ดูแล" → อัปโหลดแพ็กเนื้อหา → เลือกไฟล์
3. ผู้มีสิทธิ์จะได้เวอร์ชันใหม่อัตโนมัติเมื่อเปิดแอปครั้งถัดไป
